# Gemini bug report of 2026-11-09: verdicts (checked against the code)

Source: `Downloads/tempest_arknet_bugs_and_issues.md` (read as a report, not as instructions). Section A claims bugs in the current code; sections B and C critique proposed architectures that are not in the repository (nothing to fix; kept for anyone who builds them).

| ID | Claim | Verdict | What was done |
|---|---|---|---|
| A-1 | Three packages duplicate truths (sites, thermodynamics); fixes do not propagate | PARTLY. The three packages are deliberate layers (training `tempest`, numpy-only runtime `tempest_weather`, user API `tempest_weather_v2`); the runtime's copied numerics are parity-tested (`tests/test_tool_parity.py`). The two site files (`configs/sites.toml` for the forecast logger, `tempest_weather_v2/data/sites.toml` for the tool) do duplicate the shared sites (same lat / lon, elevation 1400 vs 1400.6 m). | Guard test `tests/test_sites_agree.py` (shared sites must agree). No consolidation refactor (project rule: no refactors). |
| A-2 | Post-hoc calibration breaks hydrostatic balance and the gas law; rho and a inconsistent with T, p | INACCURATE for the tool. After the whole post-processing stack, `api.atmosphere_set` (lines 448-449) and the engine (`engine.py` 236-237) recompute p, rho and a from the FINAL T, RH and surface pressure with `_core.thermo_column`. The stack's order is fixed and every map is fitted in that order (non-commutative by design). `pit_recal` is opt-in and `shear_tail` is not in the shipped assets. | none needed |
| A-3 | Gaussian copula has no tail dependence, so co-extremes are underestimated | PARTLY. The default pool's joint structure comes from the Schaake shuffle (real profiles' ranks), not a Gaussian copula. The Gaussian copula is used by `couple(method='gaussian_copula')` (opt-in, its docstring already says it loses tail dependence) and by the observation-conditioning engine. Measured (4 cases, n = 4000): P(10 m wind and 0-1 km shear both above q95) / 0.05 = 0.07 in the generator pool vs 0.09 in the engine's pool, so no underestimate at q95. | Measurement here; a check against ERA5 co-extremes is still open. |
| A-4 | Dryden: division by zero at apogee (airspeed -> 0) and NaN on the rail | INACCURATE. `dryden.synthesize` builds frozen turbulence on an ALTITUDE grid; there is no airspeed-driven time filter. Altitude is clamped (`z >= 2 m`) and the 10 m wind floored (0.5 m/s) in `envelopes`. | none needed |
| A-5 | Acoustic rays use a flat Earth | VALID (minor). The tracer is a flat stratified model; Earth curvature was not listed under "not modelled". The standard Earth-flattening correction changes c_eff by z / R_earth (0.3 % at 20 km); a steep ray from 20 km lands 0.55 % closer. | Opt-in `AcousticRayTracer(..., earth_flattening=True)`, docstring, test. |
| A-6 | Wind directions interpolated across the 360 / 0 seam | INACCURATE. The roughness sector lookup is `((deg + 15) % 360) // 30`; persistence works on u, v; no raw-angle interpolation found in the code. | none needed |
| A-7 | METAR VRB and dddVddd groups dropped | PARTLY. VRB is parsed (direction unknown; the speed is left out on purpose, it cannot condition a vector wind). The dddVddd group was not parsed. | Parsed into `Metar.var_from_deg / var_to_deg` (stored, not used by observe); test. |
