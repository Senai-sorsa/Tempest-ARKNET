4.1

Why Zero-PyTorch Serving Matters at the Pad

Training Tempest-ARKNET requires a heavyweight research stack: PyTorch, CUDA toolkits, Zarr chunk stores, and xarray—easily several gigabytes of compiled binaries, GPU drivers, and transitive Python wheels. Almost none of that machinery belongs inside a 6-DOF rocket Monte Carlo dispersion runner, a university flight-dynamics workstation, or an air-gapped range laptop sitting on a folding table in the New Mexico desert.

Subsystem 4 resolves that operational split by treating training and serving as strictly separated worlds. Once training and calibration finish, tempest/export_tool.py compiles every neural checkpoint, calibration quantile table, climate-index snapshot, and terrain grid into a cryptographically sealed, NumPy-only asset bundle. At query time, tempest_weather/ never imports torch, never opens a Zarr store, and never requires a GPU. Think of tempest_weather/assets/ as a sealed pocket calculator: every weight and lookup table is packed into uncompressed NumPy archives and locked behind a fail-closed SHA-256 manifest.

Four Engineering Payoffs of the NumPy-Only Contract

  • Deployment footprint drops by orders of magnitude: Shipping numpy plus a ~15–40 MB asset folder replaces a multi-gigabyte PyTorch + CUDA environment that frequently breaks across Python minor versions and OS updates.
  • Air-gapped reliability at the launch rail: Climate-mode (mode="ai") queries run 100% offline using the bundled indices.npz climate-driver snapshot and grid.npz terrain table, with zero network calls or wheel-resolution surprises.
  • Deterministic, auditable CPU numerics: Every layer in tempest_weather/engine.py executes straightforward float32 BLAS matrix multiplications verified against the PyTorch reference in tests/test_tool_parity.py.
  • Zero pickle attack surface: Every archive is loaded with np.load(..., allow_pickle=False) after whole-file SHA-256 digest verification, eliminating arbitrary Python code execution via crafted checkpoint files.

Multi-Region & Solar-Window Bundle Selection (region_assets)

A single tempest_weather/ installation can host multiple regional or diurnal asset bundles side by side—any sibling directory matching assets* that contains a valid manifest.json. When a caller invokes atmosphere_set(..., assets=None), api.py::region_assets(lat, lon, solar_hour=...) resolves the authoritative bundle in two deterministic steps:

  1. Spatial bounding-box match: Scans all assets* folders (checking the default assets directory first, then alphabetical order) and collects every bundle whose manifest["area"] latitude/longitude rectangle contains (lat, lon).
  2. Narrowest solar-hour specialist (A24): Among spatially covering bundles whose manifest["solar_hours"] interval (defaulting to [6.0, 21.0] for legacy exports) contains the query’s local solar hour, the router selects the narrowest trained window. For West Texas / New Mexico (31–34° N, 108–101° W), an all-24-hour (0–24) bundle serves every hour directly; in multi-bundle regions such as Denver (38–40° N, 106–104° W), a daytime specialist (6–21 h) automatically wins during daylight while an all-hours bundle (0–24 h) takes over at night. Queries falling outside every bundle’s trained solar window fail fast with an explicit ValueError rather than silently extrapolating into nocturnal boundary layers.

Weight Export (.npz) & Memory Footprint

Running python -m tempest.export_tool emits exactly four files into the target asset directory. Before writing a single array, export_tool.py::pack() enforces a strict architecture compatibility gate (lines 35–40): if any checkpoint specifies a non-MLP backbone (arch not in (None, "mlp")), feature interactions, product_pairs, or unsupported model_kw (anything other than mean-only X4-R harmonic climatology offsets), export immediately aborts with SystemExit. That fail-fast guard guarantees an experimental PyTorch feature can never export silently wrong into NumPy.

Memory Footprint Engineering

Every dtype choice in export_tool.py is deliberately budgeted so the entire resident asset bundle fits comfortably in a few tens of megabytes of RAM on a standard laptop:

  • Neural weights (float32): A 4-member Engression MLP (width $W = 512$, depth $L = 4$ residual blocks with FiLM/AdaLN projections and linear climate-trend slope head) stores roughly $1.5\text{M}–2.0\text{M}$ parameters per member, or ~25–32 MB across all $K = 4$ members in float32.
  • uint8 rank compression for Schaake templates: Because each calibration block has exactly $M_{\text{cal}} = 199 < 256$ members, storing integer ranks in uint8 instead of float32 profiles cuts template memory by 4×: one cell across 144 month $\times$ 2-hour bins occupies $144 \times 199 \times 179 \approx 5.13\text{ MB}$ (versus 20.5 MB in float32).
  • float16 residual pools: Historical error templates (modef_tpl/L{1,3,5,7}, $1500 \times 179$ per lead) and station/ridge residual pools are archived in float16 (2 bytes per scalar, ~0.54 MB per lead bin) and upcast on the fly during slicing.
  • Uncompressed np.savez (not savez_compressed): Deliberately trades modest disk size for near-instant cold load times—avoiding multi-hundred-millisecond zlib decompression latency on the first query.
4.3

NumPy Forward Pass & float32 Parity

The entire neural inference engine in tempest_weather/engine.py fits in fewer than 80 lines of pure NumPy. It mirrors tempest/generator/model.py::Generator layer for layer using two elementary primitives on float32 arrays: LayerNorm (_ln with $\epsilon = 10^{-5}$, matching PyTorch’s default nn.LayerNorm) and SiLU (_silu(x) = x / (1 + np.exp(-x))).

Exact Forward Pass Equations (Member.forward)

Given a batch of normalized conditioning vectors $c_n \in \mathbb{R}^{B \times F}$ split into nonlinear features $c_{\text{keep}}$ and linear-bypass features $x = c_n[:, \text{lin}]$, plus Gaussian latent noise $\varepsilon \in \mathbb{R}^{B \times d_\varepsilon}$, each ensemble member computes:

Equation 4.1 — Pure-NumPy AdaLN / FiLM Engression Forward Pass (engine.py:40–56) $$z = \mathrm{LN}_{\gamma_e,\beta_e}\!\Big(\mathrm{SiLU}\!\big(\varepsilon W_{e0}^\top + b_{e0}\big)\,W_{e2}^\top + b_{e2}\Big), \qquad h_0 = [c_{\text{keep}},\, \varepsilon]\,W_{\text{in}}^\top + b_{\text{in}}$$ $$[s_k,\, b_k] = \mathrm{split}\!\big(z W_{\text{film},k}^\top + b_{\text{film},k}\big), \qquad h_{k+1} = h_k + \mathrm{FF}_k\!\big(\mathrm{LN}(h_k)\odot(1 + s_k) + b_k\big)$$ $$\hat{y} = \mathrm{LN}_{\gamma_h,\beta_h}(h_L)\,W_{\text{head}}^\top + b_{\text{head}} + \underbrace{\sum_{j \in \text{lin}} x_{b,j}\,S_{b,j}(c_{\text{keep}})}_{\texttt{np.einsum("bk,bkd->bd", x, s)}}$$

Each residual block $k \in \{0, \dots, L-1\}$ applies an unparameterized LayerNorm $\mathrm{LN}(h_k)$, modulates it with the noise-derived FiLM scale and shift $(1 + s_k,\, b_k)$, and passes the result through a two-layer SiLU feed-forward block $\mathrm{FF}_k$. The linear climate-trend bypass head predicts per-feature slopes $S(c_{\text{keep}})$ via a two-layer SiLU MLP and contracts them with $x$ via np.einsum("bk,bkd->bd", x, s).

Round-Robin Ensemble Dispatch, X4-R Offset & Physical Decoding

At query time, Net.sample(cond, rng, eps=None) executes four deterministic steps in float32:

  1. Round-robin member slicing: Distributes the $N$ conditioning rows across the $K = 4$ independent ensemble members via strided slices cond[i::K] (matching tempest.generator.sample.Sampler identically). Each member normalizes its slice with its own (cm, cs) vectors, runs Member.forward(), and denormalizes with (tm, ts).
  2. X4-R harmonic climatology offset (x4r_offset): If the model was trained on mean-subtracted anomalies, Net.x4r_offset() locates the nearest table point in cos-lat distance $d = (\Delta \text{lat})^2 + (\Delta \text{lon} \cdot \cos\text{lat})^2$ in float64, evaluates the 11-term harmonic basis $[1,\; \sin/\cos(1..3\,a_{\text{doy}}),\; \sin/\cos(1..2\,b_{\text{hour}})]$, contracts with dc[p], zeros out any row farther than X4R_CUTOFF = 1.0°, and adds the float32 offset.
  3. Standard-pressure baseline restoration: When sp_offset is present in meta, adds _core.standard_pressure(cond[:, elev_col]).astype(np.float32) back to the surface-pressure column so the network only ever learns small synoptic pressure anomalies.
  4. Physical column decoding (Net.profiles()): Calls _core.to_physical() to invert upward vertical differences via np.cumsum along the 44-level height axis and convert log-dewpoint-depression (dpd) targets back into clipped liquid-water relative humidity.

4.4

The Public API (values, distribution, couple, atmosphere)

Every high-level query in tempest_weather/api.py funnels through one shared internal engine—atmosphere_set(lat, lon, when, n, predicted, seed, mode, **kw)—which resolves mode routing (past / forecast / ai), draws the pure-NumPy ensemble, samples vertical wind w, shifts to site elevation, integrates hydrostatic thermodynamics, and attaches 10 m gust parameters. Four focused public entry points and a concise variable DSL in tempest_weather/registry.py sit on top of that pool.

2. Variable DSL (registry.py) & Worst-to-Best flight_score

Callers address atmospheric quantities through a uniform string DSL parsed by tempest_weather/registry.py: surface keys (t2m, t2m_c, sp, rh2m, rh2m_frac, rho_sfc, gust10, flight_score), arbitrary-altitude queries {u,v,T,RH,p,rho,a,w,wind_speed,wind_dir}@z linearly interpolated across 10–18,000 m AGL, and layer queries shear@z1-z2 (m/s/km) and mean_wind@z1-z2 (25-point trapezoidal mean). When atmosphere() orders design days from worst to best, the default ranking.flight_score(atm) combines four flight-degrading metrics normalized by reference scales (higher score = worse launch day):

Equation 4.2 — Default Worst-to-Best Launch-Day Severity Score (ranking.py) $$S_{\text{flight}} = 1.0\,\frac{\overline{V}_{0\text{--}3\text{ km}}}{5.0\text{ m/s}} + 0.5\,\frac{\max_{z \le 5\text{ km}} \|\Delta \mathbf{V}/\Delta z\|}{10.0\text{ m/s/km}} + 0.5\,\frac{G_{10\text{m}}}{5.0\text{ m/s}} + 0.25\,\frac{1.225 - \rho_{\text{sfc}}}{0.1\text{ kg/m}^3}$$

A 15th-percentile call picks a plausibly severe day (85% of days are better); an 85th-percentile call picks a benign day. Teams with custom rail-clearance or apogee margins can pass any callable via score_fn=.

4. Pure-NumPy Distribution Fitting (distributions.describe) & Tail Gate

When distribution(..., setting=0) or GaussianCopula requests parametric marginals, tempest_weather/distributions/ fits candidate families matched to the variable’s physical support using pure NumPy—including Peter Acklam’s piecewise rational approximation for norm_ppf() (relative error $\approx 10^{-9}$, clamped to $[10^{-12}, 1 - 10^{-12}]$ across lower tail $p < 0.02425$, central region $0.02425 \le p \le 0.97575$, and upper tail $p > 0.97575$) paired with stdlib math.erf for norm_cdf().

Every candidate family for the inferred support (real: Normal/Gumbel; positive: Weibull/Lognormal/Gumbel/Normal; unit: Beta/Normal) must pass an IQR-normalized tail-fidelity gate across seven tail-heavy quantiles:

Equation 4.3 — IQR-Normalized Tail-Check Gate (distributions/__init__.py) $$\mathrm{err} = \frac{\max_{q \in \{0.5,\, 1,\, 5,\, 50,\, 95,\, 99,\, 99.5\}\%} \big|\mathrm{PPF}(q) - \hat{Q}(q)\big|}{\max(Q_{0.75} - Q_{0.25},\; 10^{-12})} \le \mathrm{MAX\_TAIL\_ERR} = 0.35$$

If no parametric family beats 0.35 IQR across all seven quantile levels, describe() automatically falls back to the 109-knot Empirical table and records the diagnostic reason in note. In coupling/gaussian_copula.py, parametric draws compute the normal-score rank correlation matrix, floor eigenvalues at $\ge 10^{-8}$, re-normalize the diagonal to 1, factor cholesky(corr + 1e-10 * I), and map $z = \varepsilon L^\top \to u = \Phi(z) \to x_j = \mathrm{PPF}_j(u_j)$—preserving marginals and rank correlations, though losing tail dependence and exact equation-of-state coupling ($\rho = p/(R_d T_v)$), which is why WholeSample remains the default.

5. Offline Archival & Pad Thermal Soak (coupled.py & soak.py)

For external flight simulators that ingest files on disk rather than calling Python directly, tempest/output/coupled.py::write() enforces the invariant one row is one whole atmosphere by emitting a synchronized three-file archive: (1) atmosphere_samples.npz containing all $n$ physical profiles, gust/soak arrays, and stratum_key (0–3 km mean wind); (2) atmosphere_coupling.npz containing diagnostic Pearson/Spearman matrices, 99%-variance SVD EOF modes, and 50 / 90 / 99 / 99.9 vertical-step quantiles; and (3) atmosphere_coupling.toml stamped with display_only = true and samples_sha256, explicitly warning downstream tools never to reconstruct atmospheres from summary correlations.

When propellant or avionics thermal-soak modeling requires a 24-hour pad temperature history prior to ignition, tempest/output/soak.py::Library queries training-year ERA5 hourly surface records (surface_hourly.zarr) at the same grid point and UTC launch hour within $\pm 15$ days, samples among the $k = 10$ nearest neighbors in launch t2m (optionally joint with 10 m wind via $|\Delta T|/1\text{ K} + |\Delta V|/2.0\text{ m/s}$), shifts the 24-hour temperature trace to match the Monte Carlo sample’s exact launch temperature while keeping real solar radiation (ssrd) intact, and integrates the effective soak temperature for thermal time constant $\tau$:

Equation 4.4 — Exponentially Weighted 24-Hour Pad Thermal Soak (soak.py) $$T_{\text{soak}} = \frac{\sum_{h=0}^{23} T_{2\text{m}}(t_0 - h)\,e^{-h/\tau}}{\sum_{h=0}^{23} e^{-h/\tau}}$$
4.5

Post-Generation Stack Execution Order

In a multi-stage statistical post-processing pipeline, execution order is mathematically non-commutative. Applying a shear gain map before Schaake shuffling scrambles the vertical ranks that the shear map was calibrated on; sampling the vertical-wind head after shifting profiles to pad elevation feeds out-of-distribution surface temperatures and pressures into a network trained at ERA5 grid elevation. Every serving call in tempest_weather/api.py therefore enforces a single canonical execution order that mirrors the verification scorer exactly.

Why Spatial Blending Happens via Block Allocation (Not Averaging)

The Wave-Cancellation Trap: Why You Must Never Average Atmospheres

Suppose a launch pad sits midway between four $0.25^\circ$ ERA5 grid corners. A naive spatial interpolator generates one profile at each corner and computes a bilinear weighted average of their winds. If the southwest corner draws a +15 m/s East gust while the northeast corner draws a −15 m/s West gust, averaging produces 0 m/s—an artificially calm sky that never existed at either corner. Linear averaging shrinks variance by $\sum w_i^2$ (cutting variance in half at a cell center where $w_i = 0.25$), smears razor-thin jet-stream shear layers, and breaks the nonlinear Clausius–Clapeyron coupling between temperature and humidity.

Tempest-ARKNET eliminates wave cancellation by replacing value interpolation with unbiased mixture-block allocation (OPTIONS["unbiased_blend"] = True). Because spread calibration and Schaake shuffling operate on intact blocks of exactly M_CAL = 199 atmospheres at one grid point, api.py::_blend_rows(pts, wts, groups, rng) assigns each corner $\lfloor w_i \cdot \text{groups} \rfloor$ guaranteed blocks, distributes the remaining fractional blocks via systematic remainder sampling (pos = rng.random() + np.arange(rest) on the cumulative remainder CDF—unbiased and never picking the same corner twice), and randomly shuffles the block order so any partial trailing block belongs to a random corner. (An earlier largest-remainder allocator placed corners in fixed order and sliced the tail, silently biasing Spaceport America’s 0.845 / 0.115 weights to 0.97 / 0.03.)

Sequence & Downrange Coherence Layer (coherence.py & ur5.py)

When a caller requests a multi-hour launch-hold sequence (atmosphere_sequence()) or a downrange trajectory corridor (atmosphere_downrange()), independent calls to atmosphere_set() are coupled across slices in three final steps:

  1. Gaussian Copula with Nugget $\kappa$ & Regime Lags (coherence.sequence()): Converts each slice’s whole-atmosphere permutation ranks to standard normal scores $e_k = \Phi^{-1}((r_k + 0.5)/n)$, shrinks the $K \times K$ Toeplitz lag-correlation matrix $R_d$ by nugget $\kappa_d$ (representing unshared fine-scale balloon roughness), floors eigenvalues at $10^{-6}$, factors $L_d = \mathrm{chol}(\tilde{R}_d + 10^{-9} I_K)$, and maps $z = L_d e$ back onto each slice’s exact sorted marginals. When coherence/rho_regime (C3) is exported, trajectories are stratified by their initial 0–3 km wind-shear tercile (calm / middle / windy) with distinct Cholesky factors.
  2. UR5 10 m Wind Regime Chain (ur5.py, OPTIONS["ur5_sequence"] = True): For climate-mode sequences, applies a 100-knot 10 m speed quantile map (direction preserved), scales (u, v) around the hour’s mean by (s_u, s_v), and steps consecutive hours ($0 < \Delta t \le 6\text{ h}$) through a two-regime Markov chain ($\rho = \rho_{\text{calm}}^{\Delta t}$ if previous speed $< \text{med}_{\text{ERA5}}$ else $\rho_{\text{windy}}^{\Delta t}$). Passing anchor=True orthogonalizes each member’s own 10 m rank score against $z_{t-1}$ and adjusts speed only (preventing random 10 m re-pairing from spiking median 10–50 m wind shear from 18 to 115 m/s/km), then linearly tapers the 10 m delta to zero at 300 m AGL (clip(1 - (z - 10) / 290, 0, 1)).
  3. Vertical-Wind Re-Pairing (_refresh_w(), IL-133) & Thermo Refresh: Because coherence reorders (u, v, T, RH), _refresh_w() assigns every reordered row the vertical wind w of its nearest original atmosphere in standardized profile space, then recomputes hydrostatic (p, rho, a) and 10 m gusts so every slice remains thermodynamically exact.

4.6

Vectorized Latency Budgets (~20 ms)

A rocket 6-DOF Monte Carlo sweep often queries hundreds of launch windows, sensitivity sweeps, or pad-hold hours inside a tight optimization loop. Because tempest_weather/ caches the SHA-256-verified _assets() dictionary in memory after the first call and vectorizes every neural, calibration, and thermodynamic stage over contiguous float32 arrays, a warm atmosphere_set(..., n=1024) call completes in roughly ~20 ms on a modern multi-core CPU—fast enough to run interactively on a launch-pad laptop without a GPU.

Cold Start vs. Warm Loop & Memory-Bandwidth Scaling

The very first call in a fresh Python process pays a one-time cold-start cost (~80–180 ms) to stream SHA-256 digests over model.npz, indices.npz, and grid.npz and unpack the uncompressed NumPy arrays into RAM. After that first call, every subsequent query in the same process runs at the ~20 ms warm budget. Because M_CAL = 199 quantizes batch sizes into multiples of 199 rows, querying $n = 199$ runs roughly $5–6\times$ faster (~4–5 ms), while querying $n = 200$ allocates 2 blocks (398 rows)—a useful detail when tuning Monte Carlo batch sizes.

4.7

Known Serving Edge Cases (Confirmed Bugs B1 & B13)

A full line-by-line code audit of tempest_weather/ confirmed that the core neural engine, SHA-256 integrity gate, spatial block allocator, and post-generation stack are production-solid. Two concrete serving-layer bugs were caught during the audit—both localized, easy to reproduce, and straightforward to patch.

Confirmed Bug B1 — SciPy Dependency Leak & Import-Time 4,000-Draw Self-Check (tempest_weather/ur5.py:11, 125)

Root cause: Line 11 of tempest_weather/ur5.py executes from scipy.stats import norm, silently breaking tempest_weather/’s NumPy-only runtime contract—even though pure-NumPy Acklam distributions/base.py::norm_ppf is already shipped inside the package and used by coherence.py. Worse, line 125 invokes _selfcheck() unconditionally at module import time, drawing 4,000 Gamma random variates plus 3 × 500 Markov-chain trajectories and running assertions on every single import tempest_weather.

Operational impact: (1) Importing tempest_weather crashes with ModuleNotFoundError: No module named 'scipy' in genuinely NumPy-only flight-sim environments; and (2) even when SciPy is installed, every CLI invocation or worker-process spawn pays unnecessary import-time RNG and assertion overhead.

Remediation: Replace from scipy.stats import norm at line 11 with from tempest_weather.distributions.base import norm_ppf (updating lines 30, 71, 76, and 110 from norm.ppf(...) to norm_ppf(...)), and move _selfcheck() out of top-level import execution into if __name__ == "__main__": or tests/test_ur5_port.py.

Confirmed Bug B13 — Missing support="real" Guard for degC / degF in couple() (tempest_weather/api.py:772)

Root cause: Inside api.py::distribution() (lines 755–756), Celsius and Fahrenheit temperatures explicitly pass support="real" to distributions.describe() because 0°C and 0°F are arbitrary scale origins, not physical lower bounds: 

# api.py:755-756 (distribution — CORRECT)
sup = "real" if u_ in ("degC", "degF") else None
spec = distributions.describe(ev[v], setting in (0, 1), support=sup, units=u_)

# api.py:772 (couple — BUG B13: support omitted!)
marg = [distributions.describe(table[:, j], setting in (0, 1), units=registry.units_of(v))
        for j, v in enumerate(names)] if method == "gaussian_copula" else None

Operational impact: When a caller invokes couple(..., variables=[..., "t2m_c"], method="gaussian_copula") on a warm summer afternoon where every ensemble draw happens to exceed 0°C, support_of() infers "positive" and permits positive-only Weibull or Lognormal fits on temperature—creating an artificial hard wall at 0°C and distorting lower-tail draws.

Remediation: Apply the identical support=("real" if u_ in ("degC", "degF") else None) guard at api.py:772 (or extract a shared helper _support_for_units(u_) called by both distribution() and couple()), and add a regression test in tests/test_tool_api.py asserting that warm-day t2m_c Gaussian-copula marginals never select weibull or lognormal.
