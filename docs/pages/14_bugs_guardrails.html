7.1

Training & Loss Bugs (B11, B12)

B11 · Training — FEATURES.index("year") Crashes on --features p2 (build_wdata.py:52 & s25_models.py:536)

Root cause: The 16-feature p2 climate conditioning schema replaces the raw linear "year" column with four physical teleconnection and warming drivers: (gmst, oni_pos, oni_neg, oni_lag3). However, both build_wdata.py:52 and s25_models.py:536 hardcode FEATURES.index("year") to locate the temporal trend index. Running either script with --features p2 raises an immediate ValueError: 'year' is not in list.

Guardrail & Fix: Keep --features base when invoking build_wdata.py or s25_models.py directly, or guard the lookup with "year" in FEATURES (falling back to the gmst trend column index when running under p2). Cross-ref: Stage 2.1–2.3.

B12 · Loss Gradient — Missing Epsilon Floor in energy_score Euclidean Norm (tempest/generator/model.py:395–396)

Root cause: Lines 395–396 compute the fit and pairwise spread norms directly via (samples - y.unsqueeze(1)).norm(dim=-1) and (samples[:, i] - samples[:, j]).norm(dim=-1) without adding an $\epsilon$ stabilizer inside the square root. Because $\frac{\partial}{\partial d}\sqrt{\|d\|_2^2} = d / \|d\|_2$ is undefined at $d = 0$, if two ensemble draws collide (or match $y$ identically) during early training or zero-initialized residual warm-up, PyTorch’s backward pass can emit NaN gradients that poison the optimizer state.

Guardrail & Fix: Replace .norm(dim=-1) with torch.sqrt(diff.pow(2).sum(dim=-1) + 1e-12) (or clamp_min(1e-12).sqrt()) so gradients remain bounded everywhere, including at zero distance. Cross-ref: Stage 2.2.

7.2

Calibration, Scoring & Near-Term Bugs (B4, B5, B14)

Bugs in verification harnesses and NWP ingestion are particularly treacherous because they rarely crash outright—instead, they subtly skew validation scores or inject unphysical boundary values on high-elevation launch sites.

B4 · Scoring — Inverted Post-Generation Stack Order & Missing month=mo (tempest/scoring/sonde.py:123–158)

Root cause: The radiosonde verification harness in sonde.py:123–158 applies post-generation calibration stages in an inverted order relative to the production serving engine (tempest_weather/engine.py) and omits the month=mo keyword argument when invoking the seasonal shift step. When seasonal shift tables are enabled, omitting month=mo either applies the wrong annual fallback or raises a signature/runtime error, causing offline sonde metrics to diverge from live serving behavior.

Guardrail & Fix: Always cross-check sonde calibration ablations against the canonical serving stack order in engine.py, and pass month=mo explicitly to shift.apply(). Cross-ref: Stage 3.1 & Stage 3.4.

B5 · Near-Term — 1000 hPa Relative Humidity Fallback Ignores Elevated Terrain (tempest/nearterm/ensemble.py:70)

Root cause: When surface 2 m relative humidity (rh2m) is missing from a near-term NWP ensemble member, line 70 falls back directly to the 1000 hPa pressure-level RH field. At sea level, 1000 hPa is close to the ground; at Spaceport America (~1,400 m ASL, surface pressure ~860 hPa), 1000 hPa lies roughly 1.4 km underground, where NWP pressure-level values are synthetic extrapolations rather than true boundary-layer moisture.

Guardrail & Fix: Ensure live NWP feeds supply explicit 2 m RH or dewpoint, or fall back to the lowest pressure level strictly above local station surface pressure ($p \le p_{\text{sfc}}$) instead of hardcoding 1000 hPa. Cross-ref: Stage 3.3.

B14 · Band Edges — Altitude Band-Edge Inequality Mismatch (sonde.py:265 vs. shear_map.py:27 / lapse_map.py:23 / shear_tail.py:58)

Root cause: tempest/scoring/sonde.py:265 slices vertical altitude evaluation bands using a different strict/inclusive boundary inequality (< vs. <=) than tempest/calibrate/shear_map.py:27, lapse_map.py:23, and shear_tail.py:58. Levels sitting exactly on a band edge (such as 3,000 m or 9,000 m AGL) are therefore assigned to different altitude bins during calibration fitting versus radiosonde scoring.

Guardrail & Fix: Standardize all altitude band masks across calibration and scoring modules onto a single half-open convention [lo, hi) (with the top band closed at 18,000 m) imported from one shared helper. Cross-ref: Stage 3.2 & Stage 3.4.

7.3

Serving & Conditioning Bugs (B1, B3, B13)

The serving package (tempest_weather) is engineered for lightweight, pure-NumPy execution on field laptops at the launch site. Three confirmed bugs affect dependency isolation, in-place array safety during observation conditioning, and parametric distribution fitting for sub-zero temperatures.

B1 · Serving / Import — SciPy Dependency Leak & Import-Time Self-Check (tempest_weather/ur5.py:11, 125)

Root cause: Although tempest_weather is designed as a pure-NumPy serving package, tempest_weather/ur5.py:11 executes from scipy.stats import norm at module top level, and line 125 runs _selfcheck() unconditionally at import time. In minimal NumPy-only deployments without SciPy installed, importing ur5 raises ModuleNotFoundError immediately—and even when SciPy is present, every process cold-start pays for the import-time self-check.

Guardrail & Fix: Include scipy in field-laptop serving environments until norm.ppf/norm.cdf in ur5.py is replaced with a pure-NumPy erfinv/erf rational approximation and _selfcheck() is moved into the unit-test suite. Cross-ref: Stage 4.7.

B3 · Conditioning — condition_on_observations() Overwrites S When soft=True (tempest_weather/flight/engine.py:146–155, 164)

Root cause: When soft=True is passed to condition_on_observations(), lines 146–155 and 164 mutate the ensemble matrix S in place rather than operating on a copy. Any caller retaining a reference to the prior unconditioned ensemble (for before-vs-after diagnostic plots or unconditioned baseline Monte Carlo runs) silently sees the conditioned values instead.

Guardrail & Fix: Copy the ensemble array explicitly (S.copy()) before passing it into condition_on_observations(..., soft=True), or defensively copy S on entry inside engine.py. Cross-ref: Stage 5.1 & Stage 5.2.

B13 · Serving API — couple() Omits support="real" for degC / degF (tempest_weather/api.py:772)

Root cause: In describe() (api.py:755–756), temperatures in "degC" or "degF" explicitly pass support="real" to distributions.describe() so that positive-only families (Weibull, lognormal) are never fitted simply because a summer afternoon sample happens to be entirely above 0°. However, couple() at line 772 omits that support argument when building Gaussian-copula marginals: distributions.describe(table[:, j], setting in (0, 1), units=registry.units_of(v)). For winter or upper-tropospheric profiles spanning 0°C, omitting support="real" can distort distribution fitting and truncate sub-zero tails.

Guardrail & Fix: Use method="whole_sample" (the default) when coupling temperature variables across freezing layers, or mirror the sup = "real" if u_ in ("degC", "degF") else None logic from lines 755–756 directly into line 772. Cross-ref: Stage 4.7.

7.4

Launch-Day v2 & Flight-Sim Bugs (B2, B6–B10)

The additive tempest_weather_v2 toolkit streamlines launch-day workflows, live METAR/radar ingestion, and 6-DOF flight-simulator integration. Six confirmed bugs span state resets, thread safety, unit assumptions, alias mapping, HTTP retry bypasses, and offline initialization.

B2 · Launch Day — Launch.engine() Strips _obs=None (tempest_weather_v2/launch.py:1076)

Root cause: Rebuilding or fetching the flight engine via Launch.engine() resets _obs=None at line 1076, silently discarding previously ingested launch-day METAR, ASOS, or pad-anemometer observations if called mid-workflow after observe_metar() or observe_pad().

Guardrail & Fix: Ingest live observations after constructing the engine, or verify that launch._obs is still populated before running conditioned trajectories. Cross-ref: Stage 5.2.

B6 · Flight Sim — In-Place Attribute Mutation Breaks Thread Safety (tempest_weather_v2/readers.py:347–419)

Root cause: conditions() (lines 347–352), velocity() (lines 374–379), rocketpy_inputs() (lines 395–402), and to_openrocket_csv() (lines 411–419) temporarily mutate self._ft, self.reference, self._perm, and self._sign in place inside a try/finally block. Concurrent threads sharing one Atmosphere reader race on those flags and silently corrupt units or coordinate axes.

Guardrail & Fix: Allocate one Atmosphere instance per worker thread, or parallelize Monte Carlo sweeps across separate OS processes (ProcessPoolExecutor). Cross-ref: Stage 6.2.

B7 · Monte Carlo — atmosphere_metrics() Assumes units="si" & reference="asl" (tempest_weather_v2/montecarlo.py:210–213)

Root cause: atmosphere_metrics() queries atm.air(z0 + 1.0)[2] (pad_air_density) and atm.wind_many(z0 + np.linspace(10.0, top, 24)) using z0 = float(atm.elevation_m) without inspecting atm.units or atm.reference. Passing US-unit (feet) or AGL readers silently probes the wrong altitude slice and corrupts contributions(), explained(), and run_importance().

Guardrail & Fix: Keep units="si", reference="asl" on all readers passed into montecarlo.py, and convert flight outputs to imperial units at the reporting boundary instead. Cross-ref: Stage 6.6.

B8 · Aliasing — Silent 100 m → 10 m Wind Alias (tempest_weather_v2/names.py:37–38)

Root cause: The ALIASES dictionary in names.py:37–38 maps both "wind_speed@10" and "wind_speed@100" to "wind_10m". Any user or script requesting 100 m rail-exit wind through the alias table silently receives the 10 m surface wind field instead of the 100 m AGL profile level—underestimating wind speed in the exact 50–150 m weathercocking band.

Guardrail & Fix: Query 100 m winds explicitly from the profile array or Atmosphere.wind(elevation_m + 100.0) rather than relying on the "wind_speed@100" alias. Cross-ref: Stage 5.2.

B9 · Networking — radar._get() Bypasses _net.fetch() (tempest_weather_v2/radar.py:38–40)

Root cause: NEXRAD radar fetching calls a standalone HTTP helper radar._get() instead of routing through the centralized _net.fetch() wrapper. Consequently, radar requests skip Tempest’s unified retry backoff, timeout configuration, and offline-cache replay policies.

Guardrail & Fix: Wrap NEXRAD VAD fetches in explicit caller-side exception handling during spotty range connectivity, and route radar._get() through _net.fetch() in a future patch. Cross-ref: Stage 5.2.

B10 · Offline / Stale — Offline None Elevation Crash & 6-Hour-Only Launch.stale() (tempest_weather_v2/launch.py:588, 613, 1128)

Root cause: Two related field-operations traps live in launch.py: (1) when initializing a custom coordinate offline without a cached DEM response, elevation lookup returns None and downstream initialization crashes if elevation_m was not passed explicitly (lines 588, 613); and (2) Launch.stale() at line 1128 hardcodes a single 6-hour staleness threshold rather than adapting to the observation decay constant $\tau_h = 6.3\text{ h}$ or NWP cycle cadence.

Guardrail & Fix: Always pass elevation_m=... explicitly for offline or range-site launches, and inspect the underlying observation timestamp directly when tighter launch-morning freshness gates (e.g., < 1–2 h) are required. Cross-ref: Stage 5.2.

7.5

Python 3.12 PEP 701 Compatibility Guide

Beyond the 14 logic and API bugs above, one runtime syntax detail frequently trips up users running Tempest-ARKNET inside cloud notebooks (such as Google Colab on Python 3.10 or 3.11) or older university HPC environments: tempest_weather_v2/launch.py:684 uses Python 3.12 PEP 701 nested double-quoted f-strings.

Exact Syntax & Lazy-Import Boundary

At tempest_weather_v2/launch.py:684, the error message builder embeds double-quoted string literals directly inside an outer double-quoted f-string expression: 

# tempest_weather_v2/launch.py:684 (valid on Python 3.12+ via PEP 701; SyntaxError on Python <= 3.11)
raise LookupError(
    f"no usable METAR in the {hours} h before launch from the nearest stations "
    f"({near}; tried {tried or 'none'}"
    f"{"; rejected for impossible values: " + ", ".join(rejected) if rejected else ""}). "
    f"Pass the report yourself with observe_metar(text)."
)

Crucially, tempest_weather_v2/__init__.py:12–16 isolates launch.py behind a module-level lazy __getattr__ hook so importing the top-level package stays fast and never eagerly parses launch.py: 

# tempest_weather_v2/__init__.py:12-16
def __getattr__(name):  # lazy: importing the package must stay cheap and must not need the model assets
    if name in ("Launch", "Window", "AtmosphereSet", "Launches"):
        from tempest_weather_v2 import launch
        return getattr(launch, name)
    raise AttributeError(f"module 'tempest_weather_v2' has no attribute {name!r}")

Two-Line Compatibility Workaround for Python 3.10 / 3.11 Environments

If you need the high-level Launch or Window facade on Python 3.10/3.11, extract the conditional suffix into a local variable immediately before line 684: 

rej_msg = f"; rejected for impossible values: {', '.join(rejected)}" if rejected else ""
raise LookupError(f"no usable METAR in the {hours} h before launch from the nearest stations ({near}; tried {tried or 'none'}{rej_msg}). Pass the report yourself with observe_metar(text).")
