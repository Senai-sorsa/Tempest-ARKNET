5.2.1

Launch & Window High-Level Ergonomics

Beneath the launch-day observation assimilation hooks of Chapter 5.1 sits the operational engineering layer of tempest_weather_v2/: an immutable scenario API (launch.py), human wall-clock launch windows with solar-hour gating (timeutil.py), a four-tier bare-earth elevation cascade (elevation.py), crash-safe atomic storage and retrying HTTP (_files.py, _net.py), vectorized aviation calculators (weather_calc.py), directional EPA AERSURFACE roughness and pad-anemometer calibration (roughness.py, sitecal.py), and an exact conditional Student-$t$ copula (stats.py) that keeps extreme winds locked together across altitude when a Gaussian copula lets them drift apart.

Freeze-on-Init Immutability & Scenario Branching

On launch morning, a flight-dynamics team rarely runs a single query. They compare a baseline 09:00 MDT forecast against a 13:00 MDT slip, branch a copy conditioned on a pad anemometer reading, test an alternative HRRR anchor, and export both US customary (RASAero / OpenRocket) and SI (6-DOF Python) datasets. If a Launch object were mutable, conditioning one branch or switching units in place would silently contaminate every downstream comparison sharing that reference.

At the final lines of Launch.__init__() (launch.py:153–158), the instance sets self._frozen = True. From that point on, __setattr__ rejects every external attribute write with an explicit AttributeError, permitting internal writes solely to five lazy-cache slots: _pool, _engine, _resolved, _elev, and _flags. Every modifier—.with_(...), .observe(...), .observe_hrrr(), .observe_radar(), .calibrate_site(), and .launch_week()—constructs and returns a brand-new Launch instance with its own fresh cache, so scenario trees never cross-contaminate.

The atmospheric ensemble (n=1024 by default) is never generated during construction; _ensure_pool() builds it lazily on the first call to weather(), distribution(), couple(), or atmospheres() and caches it on the instance. Meanwhile, Launch.domain() checks whether the site sits inside a trained region box, within EDGE_DEG = 0.25° (~25 km) of the boundary, or more than EDGE_DZ_M = 500.0 m from the interpolated ERA5 grid height, and reports the L3-28 Dissimilarity Index (di / di_threshold) in standardized 3D unit-sphere plus elevation space (for instance, Denver scores 21–36 against the NM/TX grid threshold of 2.5).

Wall-Clock Window: 5-Minute UTC Cells & Solar-Hour Gating

Unlike the core tempest_weather engine—which treats naive timestamps as local mean solar time—timeutil.py::Window accepts human local wall-clock times in the site's IANA time zone (loaded from data/sites.toml, passed explicitly via tz=, or inferred via sites.guess_tz() longitude bands, which automatically appends the provenance flag "time-zone-guessed-from-position"). Window.resolve() discretizes every requested interval into 5-minute UTC cells (STEP_MIN = 5):

  • Single instant: Window("2027-06-16 10:00") resolves to 1 cell (kind="single").
  • Uniform range: "2027-06-16 09:00-13:00" or a 2-tuple (earliest, latest) assigns equal probability weight across all surviving 5-minute cells.
  • Triangular peak: A 3-tuple (most_likely, earliest, latest) or keyword earliest=/latest= assigns linear ramp weights peaking at the mode (with a non-zero endpoint floor of 1e-6).
  • Multi-range & exclusions: A list of ranges with optional weights (defaulting to each range's duration in minutes) plus daily or single-date blackout intervals such as exclude=["12:00-14:00"].
  • Solar-hour cut: Each cell's mean solar hour is evaluated as $\text{sh} = (\text{utc\_hour} + \text{lon}/15.0) \bmod 24$; cells outside [SOLAR_LO, SOLAR_HI) (default 06–21 h, or the serving asset manifest's solar_hours for all-hours bundles) are dropped. ResolvedWindow records cut_share (fraction trimmed) and per-day day_share, raising WindowError if zero valid cells survive.
  • Independent vs. coupled hold hours: _ensure_pool_raw() groups sampled UTC instants by hour and flags "window-hours-independent"; for hold-time slip Monte Carlo where the same synoptic weather system evolves across consecutive hours, call launch.sequence(offsets=(0, 1, 2, 3)) instead.

Precedence & 4-Tier Bare-Earth Elevation Cascade

Surface pressure shifts by roughly ~12 Pa/m at launch-pad altitudes, so using a coarse 25 km ERA5 grid-cell elevation instead of true bare-earth pad height introduces immediate barometric and density-altitude error. Launch.elevation_info() resolves pad elevation through a strict precedence chain: explicit user elevation= → built-in or user sites.toml (e.g., spaceport_america at 1400.6 m / 7.9° E, midland at 875.0 m / 5.6° E) → the four-tier elevation.lookup() cascade, cached per coordinate rounded to 1e-5° (~1 m) in <cache>/elevation.json.

5.2.2

Aviation Calculators: Density Altitude, Crosswind & Mach

Rocket flight simulators and launch-range safety officers speak aviation and ballistics quantities—altimeter setting, mean sea-level pressure, density altitude, rail crosswind/headwind, local Mach number, magnetic declination, and drift-equivalent uniform wind—not raw model-grid geopotential profiles. tempest_weather_v2/weather_calc.py implements the core conversions in vectorized pure NumPy over the sample axis using exact International Standard Atmosphere (ISA) constants: $g_0 = 9.80665\text{ m/s}^2$, $R_d = 287.05287\text{ J/(kg}\cdot\text{K)}$, $L_{\text{std}} = 0.0065\text{ K/m}$, $T_0 = 288.15\text{ K}$, $P_0 = 1013.25\text{ hPa}$, and $\rho_0 = 1.225\text{ kg/m}^3$.

1. NWS Altimeter Setting, Exact Inverse & MSLP

When an airport METAR broadcasts A3012 (30.12 inHg), it is not reporting raw barometric pressure at the runway. It reports the NWS altimeter setting $A$: the sea-level pressure that, reduced upward through a fixed 15°C standard atmosphere to field elevation $h$ (m MSL), reproduces station pressure $p$ (hPa). By contrast, synoptic Mean Sea-Level Pressure (MSLP) reduces station pressure using the actual local pad temperature $T_s$ (K) and standard-lapse mean column temperature $\bar{T} = T_s + \tfrac{1}{2}L_{\text{std}}h$:

Equation 5.2.1 — NWS Altimeter Setting, Exact Inverse & Hypsometric MSLP (weather_calc.py:17–35) $$N = 0.190284, \qquad k = \frac{P_0^N L_{\text{std}}}{T_0}$$ $$A = (p - 0.3)\left(1 + \frac{k\,h}{(p - 0.3)^N}\right)^{1/N}, \qquad p = \left(A^N - k\,h\right)^{1/N} + 0.3$$ $$p_{\text{MSLP}} = p_s \exp\!\left(\frac{g_0\,h}{R_d\left(T_s + \tfrac{1}{2}L_{\text{std}}\,h\right)}\right)$$

Why the 0.3 hPa offset? The official NWS/ASOS formula subtracts 0.3 hPa (~8–9 ft) before reduction to account for historical cockpit-to-runway instrument height. Including the matching + 0.3 in station_pressure_hpa() makes the pair algebraically exact inverses, ensuring launch.observe(altimeter="30.12 inHg") introduces zero systematic bias into pad air density. On a hot 35°C afternoon at Spaceport America (h = 1400.6 m), MSLP sits several hPa below the altimeter setting for the exact same pad pressure; separating station_pressure, pressure (altimeter), and mslp prevents feeding sea-level METAR pressure into a simulator expecting raw pad pressure.

2. Density Altitude $h_d$

Density altitude (density_altitude_m(rho)) is the altitude in the ISA troposphere (valid to 11 km) where standard air density matches the actual moist air density $\rho = p_s / (R_d T_v)$ at the pad:

Equation 5.2.2 — Tropospheric Density Altitude (weather_calc.py:38–42) $$\beta = \frac{g_0}{R_d L_{\text{std}}} - 1 \approx 4.25588, \qquad h_d = \frac{T_0}{L_{\text{std}}}\left[1 - \left(\frac{\rho}{\rho_0}\right)^{1/\beta}\right]$$

Flight-dynamics impact: Aerodynamic normal force and drag scale directly with $\rho$. On a hot June morning at Spaceport America (4,595 ft geometric elevation), density altitude routinely exceeds 7,500–8,200 ft ($\rho \approx 0.96\text{ kg/m}^3$): rocket fins generate ~22% less corrective moment leaving the launch rail (lowering rail-exit stability margin), ascent drag drops (pushing apogee higher), and parachute terminal velocity increases as $\rho^{-1/2}$.

3. Crosswind, Headwind & IGRF-13 Magnetic Declination

Launch crews align rails into the wind using either true azimuth $\psi_{\text{true}}$ or a handheld magnetic compass reading $\psi_{\text{mag}}$, where $\psi_{\text{true}} = (\psi_{\text{mag}} + \delta) \bmod 360^\circ$. Because weather models report $(u, v)$ relative to true north, weather_calc.py::wind_from_deg(u, v) computes meteorological wind-FROM direction $\theta_{\text{from}} = (\operatorname{atan2}(-u, -v) + 360^\circ) \bmod 360^\circ$, while declination_deg(lat, lon, year=2026.0) embeds the degree-4 International Geomagnetic Reference Field (IGRF-13, epoch 2020.0) Gauss coefficients $(g_n^m, h_n^m)$ and secular variation $(\dot{g}_n^m, \dot{h}_n^m)$, converts WGS84 geodetic latitude $\phi$ to geocentric colatitude $\theta = \frac{\pi}{2} - \arctan((1 - 6.694380\times 10^{-3})\tan\phi)$, and evaluates Schmidt semi-normalized Legendre functions via _schmidt():

Equation 5.2.3 — Degree-4 IGRF-13 Declination & Rail Headwind / Crosswind Decomposition $$B_{\text{north}} = \sum_{n=1}^{4}\sum_{m=0}^{n}\big(g_n^m(t)\cos m\lambda + h_n^m(t)\sin m\lambda\big)\frac{dP_n^m}{d\theta}, \qquad B_{\text{east}} = \frac{1}{\sin\theta}\sum_{n=1}^{4}\sum_{m=0}^{n} m\big(g_n^m(t)\sin m\lambda - h_n^m(t)\cos m\lambda\big)P_n^m(\cos\theta)$$ $$\delta = \operatorname{atan2}(B_{\text{east}},\, B_{\text{north}}), \qquad \Delta\psi = \theta_{\text{from}} - (\psi_{\text{mag}} + \delta)$$ $$V_{\text{head}} = \|\mathbf{V}\|\cos(\Delta\psi), \qquad V_{\text{cross}} = \|\mathbf{V}\|\sin(\Delta\psi)$$

Rail-alignment intuition: At degree 4, declination_deg() is accurate to ~1–3° over CONUS with zero external tables, while built-in sites in sites.toml store exact pad values (7.9° E at Spaceport America). Neglecting an 8° declination offset when angling a rail into a 10 m/s wind injects a $10\sin(8^\circ) \approx 1.39\text{ m/s}$ unanticipated crosswind right off the rail and rotates the entire weathercocking and drift corridor by 8°.

4. Local Speed of Sound, Mach Number & Drift-Equivalent Wind

High-power rockets routinely cross the transonic regime ($0.8 \le M \le 1.2$) between 1.5 km and 5 km AGL, where wave drag spikes sharply and center-of-pressure shifts govern aeroelastic fin flutter. Because temperature drops roughly $6.5\text{ K/km}$ through the troposphere, the local speed of sound $a(z)$ is not a constant sea-level number—it falls from ~349 m/s on a 30°C desert pad to ~295 m/s near the tropopause:

Equation 5.2.4 — Moist-Air Speed of Sound, Local Mach Number & Drift-Equivalent Uniform Wind $$a(z) = \sqrt{\gamma\,R_d\,T_v(z)}, \qquad M(z) = \frac{V_{\text{TAS}}(z)}{a(z)} \qquad (\gamma = 1.400,\; T_v = T(1 + 0.608\,q))$$ $$\bar{\mathbf{V}}_{\text{drift}} = \frac{\sum_{k} w(z_k)\,\mathbf{V}(z_k)}{\sum_{k} w(z_k)}, \qquad w(z) = \begin{cases} 1 / v_{\text{drogue}}, & z > z_{\text{main}} \\ 1 / v_{\text{main}}, & z \le z_{\text{main}} \end{cases}$$

Descent-time drift weighting (weather_calc.py:65–74): Single-wind simulators ask for one uniform wind vector, but a plain altitude average is physically wrong for dual-deployment rockets. drift_wind() interpolates $(u, v)$ onto a 10 m grid up to apogee_m = 10,000 ft (3,048 m) with main_m = 1,000 ft (304.8 m), v_drogue = 75 ft/s (22.86 m/s), and v_main = 20 ft/s (6.10 m/s). Because the rocket spends 120 s under drogue and 50 s under main, the bottom 10% of the column receives 29.4% of the total drift weight, while vector averaging properly cancels opposing upper- and lower-level winds. weather_calc.py also provides dew_point_k() (Magnus $a = 17.62, b = 243.12$), max_shear(), and upper_wind_max() (jet-stream peak above 5 km AGL).

5.2.3

AERSURFACE Roughness Length, Log-Law & MCP Site Calibration

A 0.25° (~25 km) reanalysis cell smooths away local pad exposure: shelterbelts to the north, open alkali playa to the south, or a recessed desert basin can bias 10 m pad wind speed by 20–35% and alter near-surface turbulence intensity. tempest_weather_v2 attacks microclimate exposure from two complementary angles: land-cover physics via directional roughness length $z_0$ (roughness.py) and empirical anemometer calibration via Measure-Correlate-Predict and launch-week EWMA (sitecal.py, launch.py).

1. EPA AERSURFACE Directional Roughness & Log-uint8 Packing

Rather than querying a slow remote GIS server at runtime, roughness.py::build_sector_map() precomputes directional roughness offline from a regular NLCD land-cover raster. For every grid cell, every 30° upwind sector ($s \in \{0, \dots, 11\}$, centered on $30s^\circ$ wind-FROM bearing), and all 4 meteorological seasons (0=DJF, 1=MAM, 2=JJA, 3=SON), it computes the $1/d$-weighted geometric mean of $z_0$ over a 1 km upwind fetch ($0 < d \le 1000\text{ m}$):

Equation 5.2.5 — EPA AERSURFACE Upwind Sector Mean & Log-uint8 Encoding (roughness.py:41–84) $$z_0(s, \text{season}) = \exp\!\left(\frac{\displaystyle\sum_{i \in \mathcal{S}_s,\, 0 < d_i \le 1000\text{ m}} \frac{1}{d_i}\,\ln z_{0,i}}{\displaystyle\sum_{i \in \mathcal{S}_s,\, 0 < d_i \le 1000\text{ m}} \frac{1}{d_i}}\right)$$ $$\text{code} = \operatorname{clip}\!\left(\operatorname{round}\!\left(64\log_{10}\frac{\max(z_0,\, 10^{-4})}{10^{-4}}\right),\, 0,\, 255\right) \in \{0,\dots,255\}, \qquad z_0 = 10^{-4}\cdot 10^{\,\text{code}/64}$$

Compression without physical loss: Roughness spans four orders of magnitude—from 0.0005 m (open water) and 0.003 m (barren playa) up to 1.2 m (summer deciduous forest) in the bundled Davenport–Wieringa stand-in table data/z0_table.csv. Packing the (4, 12, ny, nx) tensor into log-coded uint8 spans 1e-4 m to ~9.65 m at a uniform 3.66% step size (±1.8% max quantization error)—far tighter than land-cover table uncertainty—at one-quarter the memory of float32. At query time, Launch._z0_samples() looks up each ensemble member's own 10 m wind direction and month; if no z0_sectors.npz covers the pad, it falls back cleanly to Z0_DEFAULT = 0.03 m (open grassland) and appends "z0-default-0.03".

2. Logarithmic Wind Profile (Log-Law) & Boundary-Layer Shear

Once $z_0$ is known for each member's upwind fetch, Monin–Obukhov similarity theory links the surface friction velocity $u_*$, aerodynamic roughness length $z_0$, and mean horizontal wind speed $U(z)$ across the atmospheric surface layer ($z \lesssim 50\text{–}100\text{ m}$):

Equation 5.2.6 — Neutral & Diabatic Logarithmic Wind Profile (Log-Law) $$U(z) = \frac{u_*}{\kappa}\left[\ln\!\left(\frac{z}{z_0}\right) - \Psi_m\!\left(\frac{z}{L}\right)\right] \qquad (\kappa \approx 0.40)$$ $$\text{Neutral height transfer } (L \to \infty): \qquad \frac{U(z_2)}{U(z_1)} = \frac{\ln(z_2 / z_0)}{\ln(z_1 / z_0)}$$

Practical pad translation: Over open desert playa ($z_0 = 0.005\text{ m}$), a 2 m tripod anemometer reads $\ln(2/0.005)/\ln(10/0.005) \approx 78.8\%$ of the standard 10 m mast wind; over shrubland or trees ($z_0 = 0.30\text{ m}$), the exact same 2 m sensor reads only $54.1\%$ of the 10 m wind. In tempest_weather_v2, per-sample $z_0$ from launch.z0() feeds directly into Dryden boundary-layer turbulence intensity, while launch.ground_wind_profile() reports the 0–200 m AGL percentiles, Weibull shape/scale parameters, and calm share (<0.5 m/s)—the exact layer that drives rocket apogee and weathercocking most strongly after pad air density.

Borrowing the wind-energy industry's Measure-Correlate-Predict (MCP) workflow, sitecal.fit_site() calibrates 10 m speeds against at least 100 paired hourly pad-anemometer readings. When applied via launch.calibrate_site(cal), _apply_site_cal() rescales wind speed while preserving direction, tapers the correction factor linearly to 1.0 by 300 m AGL (since a pad mast carries no information about free-atmosphere winds aloft), and immediately re-evaluates the 10 m gust law (_regust()).

5.2.4

Gaussian vs. Student-$t$ Copula Theory

Before modeling joint variables, stats.py::fit_best() fits six univariate families (normal, lognormal, weibull, gumbel, beta, student_t) by Kolmogorov–Smirnov distance plus a tail check at the 1st, 5th, 95th, and 99th percentiles (tol = 0.25 of the 5–95% range), deliberately preferring an unbounded family over a bounded beta whenever KS is within 0.01 so 1-in-1000 storms never receive zero probability. Real rocket launches, however, fail on joint extremes—such as a hot low-density pad paired with violent upper-level wind shear. That is the domain of stats.py::Coupled.

1. Sklar's Theorem & the 2-Step Copula Mental Model

By Sklar's theorem, any continuous multivariate cumulative distribution $F(y_1, \dots, y_D)$ can be decomposed uniquely into its univariate marginals $F_1, \dots, F_D$ and a copula $C : [0,1]^D \to [0,1]$ governing their dependence: $F(y_1, \dots, y_D) = C(F_1(y_1), \dots, F_D(y_D))$. Every parametric copula in stats.py executes the same two-step recipe:

  1. Convert to 0–100% percentile ranks: Replace every raw physical value with its empirical plotting-position rank $u_{ij} = (\operatorname{rank}_{ij} + 0.5) / n \in (0, 1)$. Units, skewness, and physical bounds vanish: a 98th-percentile pad wind speed and a 98th-percentile upper-level shear now speak the exact same unitless language—“how extreme is today compared to all other days?”
  2. Link percentiles in latent space & invert: Map the uniform ranks into latent space via $x_j = \Phi^{-1}(u_j)$ (Gaussian) or $x_j = t_\nu^{-1}(u_j)$ (Student-$t$), correlate them with a positive-definite correlation matrix $\Sigma$, draw correlated latent samples, and invert back through each variable's exact empirical quantile table via _to_data().

2. Tail Dependence: “Fair-Weather Friends” vs. Storm-Locked Extremes

The choice of latent curve in Step 2 is not cosmetic—it governs whether co-occurring extremes stay locked together or silently break apart in the 1-in-100 tail. Asymptotic upper and lower tail dependence are defined as $\lambda_U = \lim_{q \to 1^-} P(U_2 > q \mid U_1 > q)$ and $\lambda_L = \lim_{q \to 0^+} P(U_2 \le q \mid U_1 \le q)$:

Equation 5.2.7 — Asymptotic Tail Dependence: Gaussian vs. Student-$t$ Copula $$\text{Gaussian Copula } (\rho < 1): \qquad \lambda_U = \lambda_L = 0$$ $$\text{Student-}t\text{ Copula } (\nu < \infty): \qquad \lambda_U = \lambda_L = 2\,t_{\nu+1}\!\left(-\sqrt{\frac{(\nu + 1)(1 - \rho)}{1 + \rho}}\right) > 0$$

Physical mechanism (stats.py:265): Even with strong correlation $\rho = 0.7$, Gaussian density contours pinch inward at the corners; in a 1-in-100 storm, conditional correlation fades toward zero, making Gaussian variables “fair-weather friends.” In a Student-$t$ copula, every dimension shares a single random radial divisor $\sqrt{W/\nu}$ with $W \sim \chi^2_\nu$ (t = z / sqrt(chisquare(nu) / nu)). Whenever a small draw of $W$ strikes, all coordinates blow up into their tails simultaneously: for $\rho = 0.7$ and $\nu = 3$, $\lambda_U = \lambda_L \approx 0.44$, keeping extreme surface winds and aloft shear locked together.

3. Exact Conditional Student-$t$ Update (Coupled.condition())

When coupled.condition(obs) pins $d_{\text{obs}}$ observed columns (e.g., a launch-morning pad wind or temperature) to latent $t$-scores $x_o = t_\nu^{-1}(u_{\text{obs}})$, the unobserved columns $x_u$ follow an exact conditional multivariate Student-$t$ distribution (stats.py:295–317) whose degrees of freedom and scale matrix both update:

Equation 5.2.8 — Exact Conditional Multivariate Student-$t$ Posterior (stats.py:295–317) $$\mu_{u|o} = \Sigma_{uo}\Sigma_{oo}^{-1} x_o, \qquad \nu' = \nu + d_{\text{obs}}$$ $$\Sigma_{u|o}' = \frac{\nu + x_o^\top \Sigma_{oo}^{-1} x_o}{\nu'}\left(\Sigma_{uu} - \Sigma_{uo}\Sigma_{oo}^{-1}\Sigma_{ou}\right)$$

Mahalanobis surprise inflation: Look closely at the prefactor $\frac{\nu + x_o^\top \Sigma_{oo}^{-1} x_o}{\nu'}$. On a typical day ($x_o^\top \Sigma_{oo}^{-1} x_o \approx d_{\text{obs}}$), the prefactor sits near $1.0$, matching standard Gaussian Schur-complement shrinkage $\Sigma_{uu} - \Sigma_{uo}\Sigma_{oo}^{-1}\Sigma_{ou}$. During an extreme frontal passage ($x_o^\top \Sigma_{oo}^{-1} x_o \gg d_{\text{obs}}$), the Mahalanobis surprise inflates $\Sigma_{u|o}'$ above the Gaussian Schur complement—automatically widening conditional aloft uncertainty when the pad sensor reports an unusual regime, whereas a Gaussian copula shrinks conditional variance by a fixed constant no matter how shocking the observation is.

Architectural Contrast — Why Gaussian Works for Temporal Persistence (Part 4) Yet Fails for Vertical Shear (W2)

  • Smooth hour-to-hour persistence (tempest_weather/coherence.py): Synoptic air masses advect continuously over 1–6 hour hold windows. Rank changes between $t$ and $t + 1\text{ h}$ are smooth and rarely exhibit simultaneous discontinuous tail jumps across independent variables, so a Gaussian copula (paired with the UR5 10 m regime Markov chain) preserves temporal trajectories accurately.
  • Sharp vertical balloon shear (W2): Vertical soundings slice through discrete physical layers—nocturnal low-level jets, dryline inversions, and tropopause jet streaks—where adjacent altitudes undergo co-occurring extreme wind jumps. A Gaussian copula breaks those joint tails apart and under-predicts violent shear corridors; method="t_copula" (alongside whole_sample kernel-weighted resampling at width 0.3 sd) keeps extremes coupled while still supporting smooth .condition() and .adjust() stress shifts.
5.2.5

Kendall-$\tau$ Inversion, Low-Rank Compression & PSD Projection

Estimating the latent correlation matrix $\Sigma \in \mathbb{R}^{D \times D}$ and tail parameter $\nu$ reliably in pure NumPy—with zero SciPy dependency—requires careful linear algebra. Two complementary rank-based estimators exist for elliptical copulas, and both can produce non-positive-semidefinite matrices in finite samples or under low-rank truncation unless projected cleanly onto the correlation manifold.

1. Normal-Score Correlation vs. Kendall-$\tau$ Inversion

For any elliptical copula (both Gaussian and Student-$t$ with arbitrary $\nu > 0$), the pairwise rank concordance statistic Kendall's $\tau_{ij}$ satisfies the exact Lindskog–McNeil–Schmock identity independent of $\nu$ and invariant under any strictly increasing marginal transformation:

Equation 5.2.9 — Kendall-$\tau$ Inversion vs. Normal-Score Empirical Correlation $$\tau_{ij} = \frac{2}{n(n - 1)}\sum_{1 \le a < b \le n} \operatorname{sgn}\!\big((y_{a,i} - y_{b,i})(y_{a,j} - y_{b,j})\big), \qquad \rho^{\text{Kendall}}_{ij} = \sin\!\left(\frac{\pi}{2}\,\tau_{ij}\right)$$ $$\text{Fast } O(n D^2)\text{ path in \texttt{stats.py:184--187}:} \qquad z_{aj} = \Phi^{-1}\!\left(\frac{\operatorname{rank}_{aj} + 0.5}{n}\right), \qquad C = \operatorname{Corr}(Z)$$

Why both matter: Kendall-$\tau$ inversion $\rho_{ij} = \sin(\tfrac{\pi}{2}\tau_{ij})$ is completely immune to marginal tail heaviness and requires no parametric quantile map, making it the gold standard for robust pairwise correlation audits in heavy-tailed atmospheric data; however, pairwise inversion operates entry-by-entry and frequently yields a symmetric matrix $C$ with small negative eigenvalues ($\lambda_{\min} < 0$). In production, Coupled.__init__() uses vectorized normal-score correlation (avoiding $O(n^2)$ concordance loops at $n = 1024$) and then passes $C$ through the exact same spectral PSD projection required by Kendall-$\tau$ matrices.

2. Spectral Eigenvalue Clamping & Unit-Diagonal Renormalization (Coupled._fix())

Because _draw_copula() and _draw_conditional() factorize $\Sigma$ with np.linalg.cholesky(), even a single eigenvalue of $-10^{-12}$ from numerical roundoff, pairwise Kendall-$\tau$ inversion, or low-rank truncation would trigger a fatal LinAlgError. Coupled._fix(c) (stats.py:196–202) projects any symmetric candidate matrix onto the strictly positive-definite correlation cone in four exact steps:

Equation 5.2.10 — Spectral PSD Projection & Low-Rank Factor Compression (stats.py:196–216) $$C_{\text{sym}} = \frac{1}{2}(C + C^\top), \qquad \operatorname{diag}(C_{\text{sym}}) \leftarrow \mathbf{1}, \qquad C_{\text{sym}} = V \operatorname{diag}(\lambda_1, \dots, \lambda_D) V^\top$$ $$\tilde{C} = V \operatorname{diag}\!\big(\max(\lambda_1, 10^{-8}), \dots, \max(\lambda_D, 10^{-8})\big) V^\top, \qquad \hat{\Sigma}_{ij} = \frac{\tilde{C}_{ij}}{\sqrt{\tilde{C}_{ii}\,\tilde{C}_{jj}}}$$ $$\text{Low-rank } (\texttt{t\_copula}): \qquad C_{\text{LR}} = \sum_{m=1}^{k} \lambda_{(m)} \mathbf{v}_{(m)}\mathbf{v}_{(m)}^\top, \quad \operatorname{diag}(C_{\text{LR}}) \leftarrow \mathbf{1}, \quad \Sigma_{\text{LR}} = \operatorname{\_fix}(C_{\text{LR}})$$

Variance-preserving top-$k$ truncation: Setting k="auto" calls _auto_k() to pick the fewest eigenmodes explaining 95% of total correlation variance (otherwise defaulting to min(D, 6)). Restoring the diagonal to 1.0 after rank-$k$ truncation is equivalent to adding an isotropic idiosyncratic variance $1 - \sum_{m=1}^k \lambda_{(m)} v_{im}^2$ to each variable, and the final _fix() guarantees strict positive definiteness ($\lambda_{\min} \ge 10^{-8}$) before adding a tiny 1e-10 * I Cholesky guard during sampling.

3. Pure-NumPy Profile Log-Likelihood Estimation of $\nu$ (_fit_nu())

Rather than pulling in SciPy just to evaluate the Student-$t$ CDF and quantile function, stats.py:153–165 builds a 24,001-point trapezoidal lookup table _t_table(nu, half=60.0, n=24001) using only math.lgamma and np.cumsum. _fit_nu() (stats.py:218–233) then maximizes the exact Student-$t$ copula log-likelihood—the multivariate Student-$t$ log-density minus the sum of univariate Student-$t$ log-densities—across the 10-point grid $\nu \in \{2.5, 3, 4, 5, 6, 8, 12, 20, 40, 100\}$:

Equation 5.2.11 — Student-$t$ Copula Profile Log-Likelihood (stats.py:161–164, 218–233) $$\ell_c(\nu) = \sum_{i=1}^{n} \left[\log f_{t_D}(\mathbf{x}_i \mid \Sigma_{\text{LR}}, \nu) - \sum_{j=1}^{D} \log f_{t_1}(x_{ij} \mid \nu)\right], \qquad \mathbf{x}_i = t_\nu^{-1}(\mathbf{u}_i)$$
5.2.6

Lazy Package Imports & Python 3.12 PEP 701 Requirement

Because tempest_weather_v2 serves both heavy Monte Carlo launch scripts and lightweight pad-side utilities (elevation lookup, METAR parsing, aviation math, or unit conversion), its package entry point is engineered to stay instantaneous to import and strictly free of PyTorch or SciPy dependencies.

1. Module-Level Lazy __getattr__ (PEP 562) in __init__.py

Instead of eagerly executing from tempest_weather_v2.launch import Launch, Window, AtmosphereSet, Launches at package import time—which would pull in the serving engine, site tables, and network modules even when a caller only needs weather_calc.density_altitude_m()—tempest_weather_v2/__init__.py:12–16 uses Python's PEP 562 module-level __getattr__ hook: 

# tempest_weather_v2/__init__.py (lines 12-16)
def __getattr__(name):  # lazy: importing the package must stay cheap and must not need the model assets
    if name in ("Launch", "Window", "AtmosphereSet", "Launches"):
        from tempest_weather_v2 import launch
        return getattr(launch, name)
    raise AttributeError(f"module 'tempest_weather_v2' has no attribute {name!r}")

This guarantees two operational invariants: (1) import tempest_weather_v2 completes in milliseconds with zero disk I/O and zero requirement that neural model .npz assets be downloaded yet; and (2) submodules such as weather_calc, roughness, stats, timeutil, and elevation can be imported and unit-tested completely standalone in pure NumPy + Python stdlib.

Runtime Requirement — Python ≥ 3.12 (PEP 701) at launch.py:684

The moment Launch is accessed via lazy __getattr__ (or tempest_weather_v2.launch is imported directly), Python compiles Launch.observe_latest(). Line 684 nests double-quoted string literals directly inside a double-quoted f-string expression: 

raise LookupError(f"no usable METAR in the {hours} h before launch from the nearest stations ({near}; tried {tried or 'none'}{"; rejected for impossible values: " + ", ".join(rejected) if rejected else ""}). Pass the report yourself with observe_metar(text).")

Reusing the outer quote delimiter inside an f-string expression was legalized by PEP 701 in Python 3.12. On Python 3.11 or earlier, import tempest_weather_v2 itself succeeds (thanks to lazy __getattr__!), but the very first from tempest_weather_v2 import Launch immediately raises a compile-time SyntaxError—hard-enforcing pyproject.toml's requires-python = ">=3.12" floor.
