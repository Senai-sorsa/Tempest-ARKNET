7.1

Confirmed codebase bugs (B1–B14)

Every entry below was verified line-by-line against senai-sorsa/tempest-arknet at commit d081e1c, pairing each confirmed bug with the operational guardrail required until its patch lands.

By subsystem (14 total): v2 Toolkit & Flight Sim (6: B2, B6–B10) · Pure-NumPy Serving (3: B1, B3, B13) · Scoring & Near-Term (3: B4, B5, B14) · Training & Loss (2: B11, B12).

B1 · SciPy dependency leak & import-time self-check

tempest_weather/ur5.py:11,125

Root cause: ur5.py:11 executes from scipy.stats import norm at module top level and line 125 runs _selfcheck() unconditionally on import, breaking strict NumPy-only environments without SciPy installed.

Guardrail: Install SciPy in field environments until norm is replaced with a pure-NumPy erfc/erfinv helper and _selfcheck() moves behind a test hook.

B2 · Launch.engine() silently resets _obs=None

tempest_weather_v2/launch.py:1076

Root cause: Re-fetching or rebuilding the underlying engine via Launch.engine() sets _obs = None at line 1076, silently discarding previously ingested METAR, ASOS, or pad-anemometer observations.

Guardrail: Always ingest live observations (observe_latest(), observe_pad()) after constructing or accessing Launch.engine(), or re-apply observations whenever rebuilding the engine.

B3 · condition_on_observations(soft=True) mutates S in place

tempest_weather/flight/engine.py:146-155

Root cause: Lines 146-155 (and 164) overwrite the ensemble matrix S in place instead of copying it first, corrupting any caller reference held for before-vs-after diagnostic comparisons.

Guardrail: Pass S.copy() explicitly whenever retaining the unconditioned prior ensemble alongside conditioned outputs.

B4 · Inverted post-generation stack order & missing month=mo

tempest/scoring/sonde.py:123-158

Root cause: The radiosonde verification harness applies post-generation calibration stages in an inverted order relative to production serving (tempest_weather/engine.py) and omits month=mo on the seasonal shift call.

Guardrail: Never compare raw sonde.py benchmark numbers against production serving without aligning stage order and passing month=mo explicitly.

B5 · 1000 hPa RH fallback ignores elevated terrain

tempest/nearterm/ensemble.py:70

Root cause: When 2 m relative humidity (rh2m) is absent from a near-term NWP member, line 70 falls back to the 1000 hPa pressure level—which lies underground at high-elevation pads like Spaceport America (~1,400 m ASL, surface pressure ~860 hPa).

Guardrail: Verify rh2m is present in near-term feeds for high-elevation launch sites, or substitute the lowest pressure level above surface pressure $p_s$.

B6 · In-place attribute mutation breaks reader thread safety

tempest_weather_v2/readers.py:347-419

Root cause: conditions(), velocity(), rocketpy_inputs(), and to_openrocket_csv() temporarily mutate self._ft, self.reference, self._perm, and self._sign in place inside try/finally blocks, causing race conditions across worker threads.

Guardrail: Use process-based parallelism (multiprocessing) or instantiate one reader per thread rather than sharing a single reader object across concurrent threads.

B7 · atmosphere_metrics() assumes SI units and ASL reference

tempest_weather_v2/montecarlo.py:210-213

Root cause: Lines 210-213 query atm.air(z0 + 1.0)[2] and atm.wind_many(z0 + np.linspace(10.0, top, 24)) using z0 = float(atm.elevation_m) without checking atm.units or atm.reference, silently probing wrong altitudes on US-unit (feet) or AGL readers.

Guardrail: Always construct readers with units="si", reference="asl" before passing them into montecarlo.py attribution routines.

B8 · Silent wind_speed@100 → wind_10m alias

tempest_weather_v2/names.py:37-38

Root cause: The ALIASES dictionary maps both "wind_speed@10" and "wind_speed@100" to "wind_10m", causing any query for 100 m rail-exit wind via aliases to silently return the slower 10 m surface wind.

Guardrail: Query the 100 m AGL level directly from launch.atmospheres() (profile level index Z_LEVELS[2] = 100.0 m) rather than using the "wind_speed@100" alias string.

B9 · radar._get() bypasses centralized _net.fetch()

tempest_weather_v2/radar.py:38-40

Root cause: NEXRAD VAD radar retrieval calls a standalone HTTP helper radar._get() instead of _net.fetch(), skipping unified retry backoff, timeout ceilings, and offline cache replay.

Guardrail: Keep NEXRAD VAD opt-in disabled during air-gapped or spotty-cellular field runs, or wrap calls with an explicit outer timeout and fallback.

B10 · Offline None elevation crash & 6-hour-only Launch.stale()

tempest_weather_v2/launch.py:588,613,1128

Root cause: Initializing a custom pad offline without cached DEM data returns elevation_m = None and crashes downstream (lines 588, 613); separately, Launch.stale() at line 1128 hardcodes a 6-hour threshold regardless of source cadence.

Guardrail: Pass elevation_m=... explicitly for all custom or offline launch coordinates, and inspect observation timestamps directly rather than relying solely on Launch.stale().

B11 · FEATURES.index("year") crashes on --features p2

build_wdata.py:52 / s25_models.py:536

Root cause: The 16-feature p2 schema replaces raw linear "year" with physical warming and ENSO indices (gmst, oni_pos, oni_neg, oni_lag3), but both files hardcode FEATURES.index("year") and raise ValueError.

Guardrail: Guard the lookup with if "year" in FEATURES before training or rebuilding data with --features p2.

B12 · Missing $\epsilon$ stabilizer in energy_score Euclidean norm

tempest/generator/model.py:395-396

Root cause: Lines 395-396 compute .norm(dim=-1) without adding an $\epsilon$ floor inside the square root ($\sqrt{\|d\|^2 + \epsilon}$). Whenever two samples coincide ($d = 0$), the backward gradient $d / \|d\|$ produces NaN.

Guardrail: Replace bare .norm(dim=-1) with torch.sqrt(diff.pow(2).sum(dim=-1) + 1e-8) before running long or mixed-precision training jobs.

B13 · couple() omits support="real" for degC / degF

tempest_weather/api.py:772

Root cause: Unlike describe() (lines 755-756), couple() at line 772 forgets to pass support="real" for Celsius and Fahrenheit temperatures, allowing positive-only distributions to fit warm samples with an unphysical hard lower bound at 0°.

Guardrail: Request temperatures in Kelvin ("K") when using parametric copula modes in couple(), or stick to default method="whole_sample".

B14 · Altitude band-edge inequality mismatch (< vs. <=)

tempest/scoring/sonde.py:265

Root cause: sonde.py:265 slices vertical evaluation bands using a different strict/inclusive inequality than shear_map.py:27, lapse_map.py:23, and shear_tail.py:58, causing boundary altitude levels to shift between adjacent bands during verification.

Guardrail: Standardize band slicing to half-open intervals $[z_{\text{lo}}, z_{\text{hi}})$ (with inclusive upper cap only on the top band) before comparing band-level skill metrics across scripts.

7.2

Python 3.12 compatibility note

  • Delayed PEP 701 SyntaxError on Python ≤ 3.11: tempest_weather_v2/__init__.py:12-16 lazily imports launch.py inside __getattr__, so top-level imports succeed and the nested double-quoted f-string at launch.py:684 only fails when Launch, Window, AtmosphereSet, or Launches is first accessed.
  • Deployment guardrail: Target Python 3.12+ for full tempest_weather_v2 support; on Python 3.10/3.11 nodes, swap the inner quotes at launch.py:684 to single quotes or extract the expression into a local variable.
